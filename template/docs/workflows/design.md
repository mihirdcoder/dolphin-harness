# Design a journey

Layer: starter set. Keep this workflow when a user interface is designed before it is built.

Stages: design in progress, ready for owner review, accepted.

Read the capability's behavior, adjacent accepted journeys, the project's interface standard and the contracts the screens consume. Assign the design role. Define entry, exit and back behavior, the primary action, and the loading, error, empty and permission states.

Create only authorized design artifacts, with the tool named in the design role's brief. Reuse shared tokens and assets. Inspect the rendered result at the sizes and input modes the project supports. Return the artifact, the rationale, reused elements and the exact states and sizes checked. An accepted design is linked from the capability or change record.

Production implementation follows [feature delivery](feature-delivery.md) or [bounded change](bounded-change.md) and its own authorization. On a scope or contract change, return unresolved choices through [planning](planning.md). Keep the parent delivery and checkpoint across design and implementation. An accepted mockup is design evidence; it does not bypass design-review or verification gates.
